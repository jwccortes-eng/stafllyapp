# E5.7B — Visibility enum alignment (decider only)

**Status:** CLOSED 2026-06-17 · capability change only · production stays in `log_only`.

## Why

E5.7A surfaced a contract drift: the Postgres enum `profile_visibility` is

```
private | limited | public
```

but the E5.6 decider only blocked the literal string `"hidden"`, which the enum
can never produce. Under `enforce`, that would have allowed `private` and
`limited` profiles to be pushed to the external Parceros sync — the opposite of
operator intent.

## Decision

Only `profile_visibility === "public"` is publishable to the external Parceros
sync. Everything else fails closed.

| Visibility value | Behaviour under `enforce` | `blocked_reason`        |
|------------------|---------------------------|-------------------------|
| `public`         | allow (if consent granted)| —                       |
| `private`        | block                     | `visibility_private`    |
| `limited`        | block                     | `visibility_limited`    |
| `hidden` (legacy)| block                     | `visibility_hidden`     |
| `null` / missing | block (fail-closed)       | `visibility_unknown`    |
| unknown string   | block (fail-closed)       | `visibility_unknown`    |

`log_only` and `off` continue to never block. `would_block_in_enforce`
telemetry now reflects the corrected logic, so the E5.7A adoption view stays
consistent.
