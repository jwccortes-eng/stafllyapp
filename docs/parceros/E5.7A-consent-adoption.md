# E5.7A — Parceros Consent Adoption + Impact Report

**Status:** CLOSED · read-only SQL view applied 2026-06-17
**Scope:** measurement only. Enforcement (`PARCEROS_CONSENT_MODE=enforce`) is **not** activated.

---

## Objective

Provide a safe, read-only way to measure:

1. How many workers have granted Parceros `data_sharing` consent.
2. How many would be blocked if `PARCEROS_CONSENT_MODE` were flipped to `enforce`.
3. Per-tenant breakdown + a global rollup.

This is a precondition for E5.7B (real production enforcement). E5.7A does **not** change runtime behaviour.

---

## Surface

Single Postgres view:

```
public.v_parceros_consent_adoption
```

- `security_invoker = on` → each caller only aggregates rows their existing RLS already allows on `worker_profiles`, `worker_consent_records`, `worker_visibility_settings`, `employees`, `companies`.
- `GRANT SELECT ... TO authenticated`. No `anon`, no new policies, no new tables, no triggers, no materialized view, no edge function, no writes.
- One row per company plus one row with `company_id IS NULL` = global rollup across every worker the caller can see.

### Columns (no PII)

| Column                     | Type    | Meaning                                                                 |
|----------------------------|---------|-------------------------------------------------------------------------|
| `company_id`               | uuid    | Tenant; `NULL` = global rollup row                                      |
| `company_name`             | text    | From `companies.name`                                                   |
| `is_demo`                  | bool    | `companies.is_demo`                                                     |
| `is_test`                  | bool    | `companies.is_test`                                                     |
| `eligible_workers`         | int     | `worker_profiles` with `deleted_at IS NULL`                             |
| `consent_granted`          | int     | latest `data_sharing` record has `granted=true` and `revoked_at IS NULL`|
| `consent_missing`          | int     | no `data_sharing` record exists                                         |
| `consent_revoked`          | int     | latest record has `revoked_at IS NOT NULL`                              |
| `consent_denied`           | int     | latest record has `granted=false` and not revoked                       |
| `consent_error`            | int     | unmappable state (should always be 0)                                   |
| `visibility_hidden`        | int     | `profile_visibility <> 'public'` (operational reading, see Limitations) |
| `visibility_public`        | int     | `profile_visibility = 'public'`                                         |
| `would_block_in_enforce`   | int     | not granted **OR** visibility hidden (operational)                      |
| `would_publish_if_enforce` | int     | granted **AND** visibility public                                       |
| `adoption_pct`             | numeric | `consent_granted / eligible_workers * 100`                              |
| `block_pct`                | numeric | `would_block_in_enforce / eligible_workers * 100`                       |
| `snapshot_at`              | tstz    | `now()` at query time                                                   |

Zero columns expose `worker_id`, name, phone, email, address, photo, or any other PII.

## Example queries

```sql
-- Global rollup
SELECT *
FROM public.v_parceros_consent_adoption
WHERE company_id IS NULL;

-- Per-tenant adoption, real production only
SELECT company_name, eligible_workers, consent_granted,
       adoption_pct, block_pct
FROM public.v_parceros_consent_adoption
WHERE company_id IS NOT NULL
  AND NOT is_demo AND NOT is_test
ORDER BY eligible_workers DESC;

-- Tenants that still need consent UI rollout
SELECT company_name, consent_missing, eligible_workers
FROM public.v_parceros_consent_adoption
WHERE company_id IS NOT NULL
  AND consent_missing > 0
ORDER BY consent_missing DESC;
```

## Metric definitions

- **Eligible worker** = `worker_profiles.deleted_at IS NULL`. Workers without an `employee_id` are aggregated only in the global row.
- **Latest consent** = `DISTINCT ON (worker_profile_id)` over `worker_consent_records WHERE consent_type='data_sharing'`, ordered by `updated_at DESC, created_at DESC`.
- **Would block in enforce** mirrors the E5.6 decider semantics: anything that is not `granted`, or whose visibility is not `public`, would not be pushed if `PARCEROS_CONSENT_MODE=enforce`.

## Promotion criteria → E5.7B (real enforcement)

Do **not** flip `PARCEROS_CONSENT_MODE=enforce` until:

1. `adoption_pct >= 80%` for every production tenant (`is_demo=false`, `is_test=false`, `status='active'`).
2. `consent_error = 0` globally.
3. Stafly Demo behaves as expected (no false positives once a demo worker grants consent + sets visibility public).
4. ConsentCenterCard rollout reaches workers (UI prerequisite).
5. E5.5 (`shouldPublishPassport`) and E5.6 decider tests stay green (32 tests).
6. Rollback procedure rehearsed: `PARCEROS_CONSENT_MODE=log_only` returns to current behaviour in <1 min, no redeploy.
7. Explicit human approval after reviewing this report.

## Limitations

- **Visibility semantics drift.** The `profile_visibility` enum is `private | limited | public`. The E5.6 decider (`parceros-consent-decider.ts`) blocks only when the string equals `"hidden"`, which the enum can never produce. This view uses an **operational reading** (`profile_visibility <> 'public'` ⇒ hidden) so the impact numbers reflect what an operator would expect Parceros to publish. Aligning the decider to the real enum is tracked for E5.7B.
- **No daily trend yet.** `worker_consent_records` does not retain history rows (one row per worker × consent_type via the partial unique index). Trend over time will require either a separate snapshot table or reading from `parceros_consent_check` edge logs. Out of scope for E5.7A.
- **Parceros consent-check logs are not joined.** Those live in edge function logs and need a dedicated analytics query. Deferred.
